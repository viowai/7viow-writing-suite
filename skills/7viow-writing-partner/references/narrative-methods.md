# Case Narrative Method Selector

Use for choosing or developing the movement of a case study, portfolio story, project summary, or career narrative. Read the matching method details after identifying the evidence shape.

Do not use it as a universal template. Short messages, field copy, headlines, and straightforward rewrites may need an anchor and fact boundary without a case-narrative method.

## 1. Method Scope

These methods help choose a narrative order; they are not factual sources, public claims, or universal academic standards.

- `STAR-RC` extends the familiar STAR shape with `Reflection` and `Carryover` for portfolio narratives.
- Use the other method names as selection heuristics, not externally established frameworks.
- A method may organize only confirmed or explicitly provisional material. It cannot supply missing facts.
- Keep internal method labels out of visitor-facing copy unless the user explicitly requests a methodology document.

## 2. Keep Three Controls Separate

| Control | Governing question | Must not become |
| --- | --- | --- |
| Writing anchor | How should this unit sound and behave? | A source of facts |
| Narrative method | In what causal or reader-facing order should confirmed material appear? | A visible template pasted into copy |
| Fact boundary | Which claims are supported, restricted, missing, or forbidden? | A style preference |

If the user has already confirmed the information order, treat it as a dimension lock. Do not replace it merely because another method seems cleaner.

## 3. Common Visitor-Facing Movement

Most expandable cases benefit from a recognizable movement, but not identical headings:

1. Open in a real scene and explain why it matters.
2. Establish the user, role, task pressure, and constraint.
3. State the author's actual responsibility and decision scope.
4. Surface the product, editorial, or professional judgment.
5. Expand the few decisions that demonstrate that judgment.
6. Place evidence, examples, or public-safe artifacts beside the relevant claim.
7. Show what the work changed, taught, or carried into later work.
8. State the public or factual boundary where misunderstanding is likely.

This is a reading order, not a requirement to display eight labeled sections.

## 4. Selection Matrix

Choose by the narrative burden: what the reader must understand for the content to be credible.

| Internal heuristic | Use when the reader must understand | Primary movement |
| --- | --- | --- |
| Human-state-to-relationship | How a high-trust assistant or service responds to a person's changing state | pressure -> first response -> routing -> continuity -> boundary |
| Controlled task chain | How a professional workflow remains understandable, interruptible, recoverable, and reviewable | input -> decisions -> checkpoints -> recovery -> evidence |
| STAR-RC | A time-bounded project with a clear task, actions, defensible outcome, reflection, and later application | situation -> task -> action -> result -> reflection -> carryover |
| Mental-model translation | How system or domain complexity becomes language and actions a user can understand | original complexity -> user model -> translation -> first use -> continued use |
| Path reorganization under constraint | How a broken journey is reorganized while legal, safety, trust, or policy constraints remain active | break -> reorganize -> preserve constraints -> balance -> lesson |
| Multi-role workspace | How a platform serves several roles and turns repeated tasks into shared capabilities | roles -> tasks -> shared capabilities -> boundaries -> system judgment |
| Capability origin | How a career phase or body of work formed later capabilities without pretending it was one project | period -> real work -> capabilities formed -> later connection |
| Scene cluster | How repeated small situations demonstrate a pattern without being collapsed into one fictional project | scene groups -> recurring decisions -> shared lesson -> boundary |
| Expression-and-delivery origin | How early creative or client work formed communication, translation, taste, and delivery habits | context -> work types -> collaboration habits -> later contribution |

## 5. Method Details

### 5.1 Human-State-to-Relationship

Use for assistants, guidance services, onboarding, care, or other high-trust interactions.

1. Why the person enters: uncertainty, pressure, confusion, or lack of a starting point.
2. How the first interaction lowers pressure without demanding excessive trust.
3. How the system distinguishes different needs instead of giving one universal response.
4. How memory or continuity remains visible and controllable.
5. Where advice stops and user judgment resumes.
6. What this reveals about a healthy long-term relationship.

### 5.2 Controlled Task Chain

Use for professional production, review, research, or generation workflows.

1. Establish the complete task from input to usable output.
2. Explain what decision each stage carries.
3. Identify where the user must inspect, edit, confirm, or stop.
4. Show what remains traceable.
5. Show how failure returns to a usable state.
6. Conclude why control points are part of usability rather than friction.

### 5.3 STAR-RC

Use only when the source material genuinely supports all needed stages.

1. `Situation`: the professional setting, people, and constraint.
2. `Task`: the bounded responsibility or decision to be advanced.
3. `Action`: the author's actual research, judgment, design, coordination, or implementation.
4. `Result`: the defensible change. Use qualitative change when metrics are absent.
5. `Reflection`: what the author learned about the problem or method.
6. `Carryover`: how that judgment influenced later work.

Do not fabricate a result to complete the acronym. Omit or mark a stage as a gap when evidence is missing.

### 5.4 Mental-Model Translation

Use when the main contribution is making a complex system understandable and actionable.

1. Describe the original complexity and emotional or practical cost.
2. Identify how users actually understand the domain.
3. Show the translation from system categories to that user model.
4. Explain how first use reduces effort or sensitive commitment.
5. Show how explanation leads to a next action without overclaiming.
6. Show how the model supports continued use.

### 5.5 Path Reorganization Under Constraint

Use for regulated, safety-sensitive, or high-trust journeys.

1. Locate where the existing path breaks or loses the user.
2. Show which entrances, information, warnings, and steps were reorganized.
3. Preserve the constraints that must remain visible.
4. Explain the tradeoff between efficiency and protection.
5. End with the judgment that both must be designed together.

### 5.6 Multi-Role Workspace

Use for platforms serving several professional roles.

1. Identify the roles without flattening their responsibilities.
2. Name their recurring tasks.
3. Show which capabilities should be shared and which remain role-specific.
4. Cross-reference deep sub-cases instead of repeating them.
5. Explain how the information architecture follows work rather than feature inventory.

### 5.7 Capability Origin

Use for a career phase or grouped experience.

1. State the period and role honestly.
2. Name representative real work without inventing a flagship project.
3. Identify the capabilities formed through that work.
4. Connect those capabilities to later responsibilities.

### 5.8 Scene Cluster

Use when evidence consists of repeated situations rather than one bounded project.

1. State explicitly that this is a collection, not one project.
2. Group examples by scene or recurring task.
3. Attach one concrete judgment to each group.
4. Synthesize only the pattern supported across groups.

### 5.9 Expression-and-Delivery Origin

Use for supporting creative, freelance, editorial, or client work.

1. Establish the early work context.
2. Name the kinds of deliverables and collaboration involved.
3. Show how requirement translation, taste, communication, and delivery rhythm formed.
4. Keep it proportional; do not make supporting work carry the proof burden of a later specialist role.

## 6. Selection Protocol

1. Establish the target reader, surface, proof target, and fact boundary from the current brief.
2. Ask what the reader would misunderstand if the material were presented chronologically or as a feature list.
3. Recommend one primary heuristic and explain the narrative burden it resolves.
4. Combine only the parts that serve the evidence shape; the final outline must follow an intelligible reader movement.
5. Use a small natural outline when the information order is still consequentially uncertain. If the user authorizes choosing and drafting, proceed within that scope.
6. Show the outline or paragraph that expresses the decision. Keep a method note only when later work needs it.
7. Follow the actual accepted or provisionally permitted order; your method choice alone does not establish user approval.

## 7. Public Translation Contract

Internal planning may say:

```text
Primary heuristic: STAR-RC
Use for: causal order
Preserve: Reflection and Carryover
```

Visitor-facing copy should instead use natural movement and headings, for example:

```text
The task inside the original workflow
What changed in the product structure
What the work changed in later decisions
```

Do not expose labels such as `STAR-RC`, `S: Situation`, `one-line positioning`, `mental-model translation method`, or `task-chain control method` in ordinary case copy. Do not merely replace them with translated framework labels. Rewrite the page from the reader's scene and the author's real decisions.

## 8. Failure Modes

| Failure | Why it fails | Correction |
| --- | --- | --- |
| Every case uses STAR | Different evidence shapes are flattened | Select by narrative burden |
| Method chosen before facts | Structure pressures the writer to fill missing stages | Establish the fact boundary first |
| Method labels become headings | Public copy reads like an internal worksheet | Translate to natural reader-facing movement |
| A method supplies a result | Framework completion becomes fabrication | Keep the result qualitative or mark a gap |
| Several methods are blended whole | The story loses causal direction | Keep a coherent movement and use only combinations that serve it |
| A grouped career phase becomes one project | Creates false scope and ownership | Use Capability Origin or Scene Cluster |
| User reviews internal taxonomy | Attention shifts away from content quality | Show the outline or paragraph, not bookkeeping |

## 9. Finish the requested narrative

The reader can identify the author's responsibility, pivotal decisions, supporting evidence, and the outcome the sources actually establish. Distinguish a team's work from an individual's contribution. A missing quantitative result can remain a specific qualitative result; absent evidence does not become a success metric. Reflection and later application appear only when grounded in the source.

For direction-only work, deliver the distinct outline choices and recommendation. For an authorized complete case, deliver the case. Preserve accepted voice and factual scope while translating the method into natural prose.
