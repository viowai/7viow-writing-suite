# Interface copy in context

Use for page/section/card headings, compact instructions, availability counts, action feedback, and footer copy. Read the surrounding screen and the user's actual action; isolated wording cannot reveal repeated context or a misleading state.

- Preserve the intended task behind draft wording. Unless the wording is explicitly locked, replace an awkward or redundant label with a clearer one and explain the concrete benefit briefly. Treat a confirmed name or business rule as a constraint, not as an editable style suggestion.
- Use the product and selected navigation as established context. Remove an eyebrow that repeats them. Where useful, combine the current object and task in the main title. Honor a declared presentation-depth limit, such as title plus necessary support; do not preserve a third line because a template has one.
- Omit a total that only restates a small visible set. Follow a supplied threshold rather than inventing a universal one. State the quantity the reader needs, such as “8 remaining”; use fractions for a real progress/position relationship, not as decoration.
- Split independent operating rules into separate statements or fields when that improves scanning. Preserve actors, triggering events, duration, exceptions and consequences. Keep continuous argument as prose when its clauses depend on one another.
- Give a notification preview readable fields while retaining the exact copyable message's required information. A split/combined rewrite still needs a source-to-result meaning check.
- Express the actual outcome and recovery. Distinguish business rejection, warning, technical failure and success. Hand off the required semantic treatment to the UI owner; prose alone cannot prove a toast was seen or a control worked.
- Check the whole visible response to an event. A field/form error and a simultaneous toast repeating it are duplicate feedback even if each sentence is individually clear. Select one primary location and keep the recovery instruction there.
- After expiry or revocation, do not describe a former deadline as currently valid. A transient success message and the item's lasting state serve different purposes; remove redundant success paragraphs that add neither information nor action.
- Keep the footer for useful declarations, confirmed copyright or attribution, and necessary links. Do not repeat the site introduction or invent ownership. Distinguish the business producer, rights holder, and linked-site owner; a software author or license identity is not automatically the product publisher.

If the user supplies a rule such as a two-level cap or a five-item count threshold, preserve it in the task's source and apply it exactly there. Reusable guidance should retain the decision logic without presenting that private preference as an industry standard.

Deliver the edited copy and any behavior-dependent verification needed from the interface owner. Keep source traces, editorial instructions and unresolved design notes outside product copy.
