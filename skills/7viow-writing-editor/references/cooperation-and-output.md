# Scoped Editorial Support and Delivery

Use when another writer owns the artifact, feedback crosses roles, or a real transfer is needed. This reference does not require a universal handoff form.

## Establish the current assignment

Use the actual draft or source location, current audience and purpose, accepted voice and wording, factual limits, permitted change, and the next deliverable. Reuse earlier decisions and task authorization within their scope. A clear ordinary-language replacement or approval is sufficient; ask only when its referent changes the work.

Partner owns author-voice exploration when that is the current problem. Deck owns the page system when the requested result is a presentation. Editor owns direct editorial delivery. The current lead remains responsible for its agreed unit; editing one sentence does not transfer the whole project.

## Return support that can be integrated

Return located findings at the requested review scope, including proposed repairs when requested. Apply a bounded revision when it is authorized. Preserve the content owner's accepted voice, order, and exact phrases. If solving the defect would change the central claim, page responsibility or another protected dimension, identify that precise conflict and a supported alternative; do not silently broaden the assignment.

For deck support, keep meaningful comparisons and necessary on-screen qualifiers. A shorter sentence that moves the only evidence limit into speaker notes is not a faithful local edit. Return the revised text in the supplied page structure when requested.

The owning writer integrates permitted changes once, checks their affected context, and returns a coherent result. Already decided preferences do not need to be re-interviewed by a supporting role. Consult only the role that resolves an actual issue; three available skills do not imply a three-stage pipeline.

## Finish or transfer

A rewrite returns usable copy and material notes; an audit returns findings; a file edit returns saved locations and actual readback. A substantive omission outside the editing scope is a proposed decision, not an invisible style fix.

When the user changes the main job or a different owner must finish the result, pass the current text, sources, accepted decisions, relevant rejection reasons and exact next task. Distinguish candidate completion from user approval and actual distribution. Creating a new task or agent, storing durable memory, or sending the work is a separate action, governed by the user's actual authorization.
